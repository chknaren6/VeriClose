# Five-minute VeriClose walkthrough

## 0:00–0:40 — Problem

The same settlement appears as gateway components, bank cash and ERP journal lines. A shared amount
or reference is insufficient proof because duplicates, timing shifts and incorrect accounting can
look superficially correct.

## 0:40–1:30 — Import and validation

Show the three upload slots. Explain that mappings are versioned and confirmable. Open source
inspection to show resolved fields, raw sample rows, validation errors and control totals.

## 1:30–2:20 — Run cockpit

Show verified, review/unresolved and amount-at-risk values. State explicitly that these are
operational results. Precision and recall exist only in the hidden-truth benchmark.

## 2:20–3:50 — Exception and evidence

Open one unresolved case. Ask the practitioner to inspect it without coaching. Show gateway, bank
and ERP rows, original fields, file/row lineage, settlement equation and proof checks only after the
initial observation.

## 3:50–4:30 — Review state

Show that a classification and note can be recorded without altering source evidence or the
system's historical decision. Explain that journal posting is not available in this milestone.

## 4:30–5:00 — Safety and review goal

Arithmetic, proof, auto-clear and journal balance remain deterministic. AI is optional advisory
space. The purpose of this session is to discover wrong assumptions and missing evidence—not to
ask whether the interface looks impressive.
